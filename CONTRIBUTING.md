# Contributing

## Development rules

1. Keep changes small enough that the Git history explains what was built
   during the hackathon.
2. Never commit private keys, API keys, RPC credentials, wallet seeds, or
   populated `.env` files.
3. Add tests with every behavioral contract change.
4. Record material architecture decisions in `docs/DECISIONS.md`.
5. Record material AI-assisted specifications in `prompts/` and summarize the
   assistance in `docs/AI_USAGE.md`.
6. Identify every imported library, template, or external codebase in
   `docs/PROVENANCE.md` before merging it.

Run all checks listed in `README.md` before pushing.
